# Architecture Review
Generated: 2026-07-27T17:59:58.547Z

## Summary
The codebase is well-documented and mostly follows a consistent 'pre-built component, don't reimplement' philosophy (Card, Amount, CountUp, ScreenScaffold, etc. are all reused correctly). However, the documented service-injection seam (AppProviders/useServices) is entirely unused — every page bypasses it and imports lib/storage and lib/taxEngine directly — and there is real duplication around haptic-firing boilerplate, zero-deduction constants, and reward-ad logic. No circular dependencies were found and folder structure is sound overall.
